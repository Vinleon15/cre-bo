# tokensave

Экономия токенов при работе с Claude API без потери качества.

Принцип: экономим не на нужной информации, а на **повторной обработке уже известной**.

```python
from tokensave import Saver

saver = Saver(mode="normal", session="проект-1")
a = saver.ask("Какой срок оплаты?", files=["dogovor.pdf"])
print(a.text)
print(f"экономия {a.saved_pct:.0f}%", a.warnings)
```

```bash
pip install -r requirements.txt
python -m tokensave.selftest    # самопроверка, API не трогает
python -m tokensave.report 30   # сколько сэкономлено за 30 дней, в $
```

## Три механизма

| Механизм | Эффект | Риск для качества |
|---|---|---|
| `cache.py` — prompt caching | повторный префикс стоит 0.1x | нет |
| `files.py` — кэш файлов по sha256 | файл разбирается один раз на версию | нет |
| `history.py` — сжатие истории | ~59% на треде из 60 ходов | есть, поэтому `guard.py` |

Историю приходится сжимать, потому что API без состояния: весь тред
пересылается каждый ход, и суммарный расход растёт квадратично (`L·N²/2`).

## Почему это не портит ответы

- **Пины.** Цифры, даты, суммы, сроки, условия и решения выносятся из
  вытесняемых ходов дословно и живут вечно. В пересказ они не попадают.
- **Теряемые слои документов** — сноски, комментарии Word, скрытые листы
  Excel, заметки докладчика PPTX — извлекаются всегда и подаются целиком.
  Скан без текстового слоя помечается как «непрочитан», а не как «пустой».
- **Жёсткий override.** Расчёты, договоры, сверки, сравнение версий →
  режим принудительно `full`, настройка экономии игнорируется.
- **Эскалация.** Если модель сообщила о нехватке данных или в ответе
  всплыло число, которого не было в контексте, запрос повторяется с полным
  контекстом. Вниз по лестнице система не спускается никогда.
- Дешёвая модель (`claude-haiku-4-5`) используется только для внутренней
  механики — сводок и классификации. Финальный ответ всегда на основной модели.

## Режимы

| | история | файлы | effort |
|---|---|---|---|
| `economy` | 4 хода + сводка + пины | оглавление | low |
| `normal` | 12 ходов + сводка + пины | релевантные части + окрестности | high |
| `full` | всё | целиком | max |

## Что где лежит

`~/.tokensave/store.db` (переопределяется `TOKENSAVE_DB`): разбор файлов,
чанки, сводки сессий, пины, журнал токенов. **Оригиналы файлов не изменяются
и не перемещаются** — в базе только производные данные, пересоздаваемые заново.

## Ограничения

- Только Anthropic API. Для OpenAI нужен отдельный адаптер (не сделан).
- Веб-интерфейсы chatgpt.com и claude.ai автоматизировать нельзя — контекст
  там собирает провайдер, а браузерная автоматизация нарушает их правила.
- PDF без текстового слоя требует OCR; сейчас такой файл только помечается.
- Экономия в `report` считается против baseline «вся история + файлы целиком
  без кэша», измеренного через `count_tokens`.
